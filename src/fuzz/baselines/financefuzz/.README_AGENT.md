# baselines/financefuzz/ — FinanceFuzz competitor

Faithful reimplementation of **FinanceFuzz** (Gan et al., 2025; paper PDF in
`research/related_work/financefuzz_paper.pdf`) — a ConFuzzius fork whose novelty is a
**financial-property oracle**. Upstream reference (ported from, MIT): `ref/FinanceFuzz`.
This baseline uses **their** model (seed-gen + GA + oracle + T→T′); the ONLY thing reused
from our project is the **forge harness as the EVM execution backend** (replacing
upstream's instrumented py-evm). Not RL/LLM; does NOT use `common/loop.py`.

## Files
- `generator.py` — port of upstream `Generator`: ABI→per-function arg types, boundary-aware
  arg sampling (`UINT_MAX`/`INT_MAX`/`INT_MIN`, triangular boundary seeds), `CircularSet`
  ring buffers, caller/value pools. An individual is a list of `Tx` → our call-list
  `[name, args, value_wei, caller]`.
- `engine.py` — port of the ConFuzzius GA: `Individual`/`Population`, linear-ranking
  selection, concatenation crossover (pc=0.9), per-gene mutation (pm=0.1), `next_generation`
  (+light elitism). Fitness supplied by the runner.
- `oracle.py` — port of the detectors. **Invariant**: token-supply, checked **per call**
  (faithful to upstream `TokenBalanceDetector`, run around each tx) — sum of `balanceOf` over
  *that call's* Transfer-changed accounts (mint/burn excluded) must be conserved. Per-call (not
  per-sequence) so a legit mid-sequence mint can't leak into the diff and false-positive on a
  mintable ERC20. **Equivalence**: build T′ variants +
  diff fingerprints — `TOD` (reorder by sender), `TIME` (warp), `REENTRANCY` (armed-vs-unarmed
  pair), `GASLESS` (reject-recipient + `is_success` fail-set gate).
- `execution.py` — `FinanceExecutor(FoundryFuzzer)`: overrides `_build_test` to render
  `templates/finance.sol.tpl` (runs T + all T′ in ONE forge test via snapshot/revert,
  emits `FF_BLOCK`/`FF_FP`/`FF_INV`). **Each block (`_t_block` / `_variant_block`) MUST wrap its
  body in its own `{ }` scope** — all blocks share the single `test_fuzz_input()` function scope,
  and the per-call temps `_render_sequence_call`/`_render_args` emit (array-arg memory temps
  `_arr_<callidx>_<slot>`, bound-return locals `_ret<idx>`) key off the call index, so identical
  identifiers recur across blocks; without the brace, solc rejects the redeclaration (error 2333 —
  was the Bancor/SwarmMarkets CompileError). GA eval = json-only (`run_individual`); plus one `--debug`
  `run_coverage` dump per generation on that gen's best individual (fills per-iter
  `coverage_bc_branch_ids` for F2; the dumps also feed cumulative summary coverage) + one final pass.
- `runner.py` — `run_financefuzz(config, source, abi, *, generations, population, … ) ->
  (bugs, run_log)`. GA generation loop; emits standard `report.py` records. `generations`
  defaults to `config.max_iterations // population` (regime budget).

## Oracle output contract (parsed in `oracle.py`)
- `FF_BLOCK <tag>` precedes each block; `[<idx>] … fail` lines after it = that block's revert set.
- `FF_FP <tag> <acct_idx> <eth_wei>` / `FF_FP_TOK <tag> <acct_idx> <token_bal>` = per-account fingerprint.
- `FF_INV <pre_sum> <post_sum>` = ONE line PER CALL in the T block — that call's changed-account
  token-balance sum, before vs after the call (captured by `_ffBalances`/`_ffInvEmit`). The oracle
  flags if any line has pre != post. A call with no non-mint/burn Transfer emits no line.
Tags: `T`, `TOD`, `TIME`, `REENT_OFF`/`REENT_ON`, `GASLESS`. Equivalence detectors diff each
vs `T` (reentrancy diffs `REENT_ON` vs `REENT_OFF` — identical callers, isolates re-entry).

## Documented backend adaptations (vs the paper's instrumented py-evm)
1. **Reentrancy** & **gasless-send** are forge approximations (cheatcodes), not opcode
   instrumentation: reentrancy = armed-vs-unarmed unified `Attacker` pair; gasless = `vm.etch`
   `FFRejectEther` onto `attacker_address` + the fail-set `is_success` gate. (TOD/timestamp are faithful.)
   TOD reorder is deterministic (reverse first-appearance) so T′ differs from T **when the sequence has
   ≥2 distinct senders**; with the unified single attacker identity most FF sequences are single-sender,
   so the TOD variant usually equals T (no signal) — TOD is effectively dormant post-unification.
2. Dropped py-evm-only seed env fields (`call_return`/`extcodesize`/`returndatasize`/`blocknumber`);
   per-tx timestamp handled by the warp variant, not the seed.
3. GA uses plain (non-taint) linear-ranking + concatenation operators — ConFuzzius's
   data-dependency variants need its symbolic taint analyzer (no forge equivalent).
4. Fitness = log-derived (successful T calls + length + violations), not branch coverage, to
   avoid a per-eval `--debug` dump over the 5-block differential test (multi-GB on re-entrant
   loops). Coverage is dumped once per generation on the best individual (+ a final pass) — enough
   for a sparse per-iter F2 curve and a fuller summary figure, without paying the dump on every eval.
5. **Modern (>=0.8) deploy path only** (`finance.sol.tpl` uses `new T(...)`). Legacy (<0.8)
   SmartBugs rows are skipped (logged); FinanceFuzz's own dataset is the natural inline ground.

## Harness additions (single-source `fuzzer/templates/Harness.sol`, unused by other modes)
`_ffBalances`, `_ffInvEmit` (per-call invariant), `_ffEmit`, `_ffChangedAccounts`, and the
`FFRejectEther` contract. Plus
`templates/finance.sol.tpl`. Other modes' templates are untouched.

## Fixtures + smoke
`data/examples/FF_{TransferMint,TOD,Timestamp,Reentrancy,GaslessSend,Benign}.sol` — one per
property + a benign control. Verified: each vulnerable contract fires its detector;
`FF_Benign` fires nothing. CLI: `uv run sc-fuzz financefuzz <proj> <C> --abi … --source …
--generations N --population M`. Unit smoke: `tests/test_financefuzz.py` (no forge/LLM).
