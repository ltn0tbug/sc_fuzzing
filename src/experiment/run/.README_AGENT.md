# src/experiment/run — unified experiment runner

One CLI + one resumable driver over a **method × dataset registry**. Commands → `../../../COMMANDS.md`.

## Files
| File | Role |
|---|---|
| `run.py` | CLI + resumable driver loop (single entry point) |
| `registry.py` | `METHOD_SPECS` + `DATASET_SPECS` — declarative wiring (mirrors `fuzz.report.REPORT_SPECS`) |
| `scaffold.py` | Foundry scaffolding (inline + fork), dispatched by `Contract.kind`; `RPC_ENDPOINTS` (chain→**list** of archive endpoints), `resolved_endpoints`, `preflight_fork` (RPC health + cache warm gate). Fork builds pin the exact on-chain compiler settings (optimizer/runs/evm in `foundry.toml` + `_pin_target_pragma` → the target's exact solc) so the recompiled bytecode matches on-chain (coverage fidelity); resolves `ForkConfig.code_address`/`is_proxy` (impl for a proxy) |
| `exp_profile.py` | regime/backend knobs (`EXPERIMENT_MODE`, `LLM_BACKEND`, `SKIP_ON_FAIL`, madfuzz seed knobs) |
Hyperparam defaults → `src/fuzz/profiles.py` (`<method>_defaults`); `MethodSpec` references them,
`run.py` calls `.materialize(mode=…)`.

## Flags
| Flag | Default | Meaning |
|---|---|---|
| `method` (pos) | — | `sscfuzz\|sscfuzz_dqn\|sscfuzz_esb\|sscfuzz_cb\|rlfuzz\|madfuzz\|randomfuzz\|llmfuzz\|financefuzz\|all`. **`sscfuzz` is an ALIAS → `sscfuzz_esb`** (switching bandit, the RQ3a-recommended selector; runs into the `sscfuzz_esb/` dir). `sscfuzz_dqn` = the factored-DQN selector (former default). `sscfuzz_cb` = LinUCB contextual-bandit variant. Aliases (`registry.METHOD_ALIASES`, resolved by `resolve_method`) are valid choices but NOT iterated by `all`. |
| `--dataset` | required | `smartbugs`(inline) \| `defihacklabs`(fork) |
| `--mode` | `exp_profile.EXPERIMENT_MODE` | `test`(15)/`medium`(50)/`long`(100)/`very_long`(500) |
| `--backend` | `exp_profile.LLM_BACKEND` | `anthropic\|claude-code\|llama-cpp` (LLM methods) |
| `--iterations N` | — | raw count, overrides the `--mode` budget |
| `--only <id>` | — | one contract id |
| `--verify` | off | write `output/experiment/_verify/`, bypass registry (needs `--only`) |
| `--output-dir <path>` | `output/experiment/` | override the results ROOT → full registry run lands under `<path>/<dataset>/<method>/` (still resumable); use it to run the whole matrix without clobbering canonical results |
| `--no-skip-on-fail` | off | abort on first crash vs log+continue |
| `--checkpoint-every N` | `exp_profile.CHECKPOINT_EVERY`(25) | inner-resume flush cadence in iters; 0=off |
| `--keep-checkpoint` | off | on clean completion keep a final checkpoint at the true last iter (not cleared) → re-run same id with higher `--iterations` to CONTINUE (e.g. 100→200) |
| `--skip-preflight` | off | skip the fork-infra pre-flight gate entirely (fork datasets only) |
| `--skip-warmup` | off | run the pre-flight RPC health check but skip the forge-cache warm-up (fork only; caches warm lazily in-run) |
| `--debug` | off | per-iteration logging |
**Two resume layers.** Outer (contract): ids in `output/experiment/<dataset>/<method>/_summary.json`
skipped on re-run; Ctrl+C flushes partial summary. Inner (iteration, `fuzz/checkpoint.py`): every
method's loop flushes full resumable state to `<method_dir>/_ckpt/<safe_id>.ckpt.pt` every
`--checkpoint-every` iters, so a contract killed mid-run (Ctrl+C / OOM) resumes from the last flush
instead of iter 0. Per-iter run-records go to a sidecar `<safe_id>.records.jsonl` (appended, not in the
checkpoint blob — keeps it constant-size on very-long runs); resume reads them back truncated to the
flush iter. Runner sets the path + clears both on clean completion; disabled in `--verify`.
**Continue a finished run (`--keep-checkpoint`):** the loop writes ONE final checkpoint at the true
last iter (e.g. 110, not the last every-25 flush) and the runner does NOT clear it; a re-run of the
same id with `--iterations` above that iter resumes+extends (replacing its `_summary` row) instead of
skipping. Same primitive on standalone `sc-fuzz` commands via `--checkpoint-path` + `--keep-checkpoint`.

## Fork pre-flight gate (`scaffold.preflight_fork`, fork datasets only)
Runs ONCE in `run.py::main` before the method loop (shared across `all`); inline datasets skip it.
Two stages:
- **D. RPC health** — for each required chain, probe its `RPC_ENDPOINTS` list with an `eth_getBalance`
  at the fork block (ARCHIVE check, at the OLDEST block on that chain). Reorders `_SELECTED_ENDPOINTS`
  so a live endpoint leads (scaffolding + `ForkConfig.rpc_endpoints` read it). **HARD gate:** a required
  chain with 0 live endpoints ABORTS the run (`sys.exit`) instead of emitting `fork_setup_failed` for
  every iter.
- **E. Cache warm-up** — one successful `setUp()` per fork contract (scaffold+build+run an empty
  `FuzzInput`) so `~/.foundry/cache/rpc/` is warm before measured iters. Best-effort + REPORTED
  (warm/cold summary); a cold contract is retried in-run (foundry.py fork retry), so it does NOT abort —
  only a dead chain (D) does. `--skip-warmup` runs D only; `--skip-preflight` skips both.

## Registry-driven loop
```
run.py reads METHOD_SPECS[method] (entry fn, defaults, uses_llm, extra_kwargs)
              DATASET_SPECS[dataset] (kind, results_subdir, filter_skip)
              exp_profile.py (mode, backend, skip-on-fail, madfuzz knobs)
for c in schema.load_dataset(dataset):
    scaffold.prepare(c, dataset_spec)          # scaffold → forge build → load ABI
    cfg = defaults.materialize(mode, fork=…)   # + backend / max_iterations overrides
    _build_config threads the WHOLE extend bag onto cfg → orchestrator.py/loop.py → FoundryFuzzer:
       external/setup_template (fork + inline escape hatch),
       constructor_args/value, pre_deploy/setup_calls (inline co-located deps).
       ⚠ all of these must reach FoundryFuzzer or dep-needing rows silently mis-deploy
         (e.g. SmartBugs PrivateBank → null Log → Deposit reverts → false no-bug).
    bugs, run_log = method.entry(cfg, source, abi, **extra_kwargs)
    persist run_log + append _summary row
```
Add a method = 1 `MethodSpec` in `registry.py` + `*_defaults` in `profiles.py`. No new runner file.

## Output
Repo-root `./output/experiment/<dataset>/<method>/` (set by `scaffold.RESULTS_ROOT`; logs sit beside summaries).
```
output/experiment/
├── smartbugs/<method>/{_summary.json, <category>_<address>.json, _ckpt/<safe_id>.{ckpt.pt,records.jsonl}*}  ← smartbugs (inline)
├── defihacklabs/<method>/{_summary.json, defihacklabs_<safe_id>.json, _ckpt/…*}  ← fork
└── _verify/<dataset>/<method>/                                     ← --verify (no registry)
```
`_ckpt/*` = transient inner-resume checkpoints (deleted on clean completion; present only after an
interrupt). Each run_log now also carries a per-iteration `learning` block (cum_reward /
cum_unique_bc_branches / cum_bugs / wall_ms + RL epsilon/td_loss/q_chosen) and a
`summary.learning_curve` (compact coverage/reward curves + first_bug_iter / coverage_saturation_iter /
quartiles / final_epsilon / mean_loss_last_decile) — surfaced flat in EDA (`../eda/outcomes.py`).
`_summary.json` row: `{id, status∈(ok|skip|build_fail|run_fail), target, elapsed_s, bugs,
total_reward, bc_branches_hit, bc_branches_total, bc_coverage_ratio}` (+`category` smartbugs /
`chain` + `coverage_unreliable` defihacklabs — the fork SOURCE tier drifted from on-chain, so
source coverage is suppressed while bc/function stay on-chain-anchored; see fuzzer coverage-fidelity).
Companion `<safe_id>.json` = full run_log (`summary`+`iterations`+`bugs`) from
`fuzz.report.build_run_summary`. Analysis reads these via `../eda/` (`outcomes.py`→`dataframe.py`).
